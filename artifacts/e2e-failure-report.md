## Evidence and diagnosis

### Test-maintenance fixes (#7, #8, #9, #12)

- **#7 source control:** the global `Retry` role locator could bind to a duplicate banner that detached during refresh. The patch locates the button from the visible too-many-changes banner's parent and preserves every recovery assertion.
- **#8 browser reconciliation harness:** the file-preview action no longer represented the managed-browser create contract under test. The patch drives `openNewBrowserTabInActiveWorkspace`, retains the returned promise while the fault seam is held, and compares stable host state without publication counters. Page creation, rollback, and capability assertions remain intact.
- **#9 cookie survival:** the test opened a new page as soon as the replacement runtime ID and worktree appeared, before existing client-hosted page ownership had been reclaimed. The patch synchronizes on the runtime's authoritative page-ID inventory, then performs the unchanged rendered-cookie and partition assertions.
- **#12 active delete:** a synthetic DOM `contextmenu` event and the obsolete exact name `Delete` bypassed Playwright's input behavior and missed the current descriptive accessible name. The patch uses a real right-click and `^Delete(?:\s|$)` while retaining viewport, removal, and scroll-position checks.

### Flake fixes (#4, #11)

- **#4 tabs:** the test measured its initial tab count before startup worktree refresh settled, allowing hydration to add a tab alongside Cmd/Ctrl+T. It now waits on the repository's startup refresh readiness signal and still asserts an exact `+1` delta. The original failure did not reproduce in three pre-patch current-main runs; three post-patch runs and the eight-test file suite passed.
- **#11 tooltip:** terminal output movement invalidated the cached cell coordinates used on every poll, so later mouse moves could target stale geometry. Each poll now re-locates the URL before moving the pointer. Tooltip visibility and full URL text assertions are unchanged; three consecutive post-patch runs passed.

### Product failures (#1, #2, #3, #5, #6, #10, #13, #14)

- **Paired browser creation/routing (#1–#3):** three independent user flows fail after healthy worktree and terminal setup: managed client-hosted creation is rejected, Cmd-J omits the expected host-qualified page, and a remote-pane link never acquires client placement. The expected local-SSH guard message also appears in passing paired tests and is not the root cause. Each exact scheduled test remains listed separately.
- **Duplicate PTY reveal (#5):** ownership repair converged to one pane/renderer, but the revealed renderer painted the normal buffer instead of the authoritative alternate buffer. The current-main replay passed once; repeated prior scheduled evidence on STA-5208 prevents treating the original as a locator or startup failure.
- **Daemon unwedge (#6):** both CI and exact current-main replay stop at `workspaceSessionReady=false` for 30 seconds. This confirms a startup-readiness defect, but the test never reaches its later typing assertion; the terminal-input behavior is therefore an `UNCONFIRMED PRODUCT_BUG` candidate, `BLOCKED` pending the readiness fix and replay.
- **Completed worker (#10):** the live pre-activation recovery record changes to `done` where the retirement contract requires `working`. The same assertion fails on current `main` and remains enabled.
- **Escape routing (#13):** after the first Escape closes the composer, the second Escape does not leave Automations. The exact test reaches this assertion and fails on current `main`.
- **Empty-workspace activation (#14):** the durable closed-tab tombstone survives restart correctly, but explicit sidebar activation leaves a blank zero-tab workspace. The regression assertion was reviewed and retained unchanged.

The repeated `Execution context was destroyed` pattern was treated as a session/startup failure signal, not as proof of a product assertion. None of the 14 rows was classified from that message alone. Additional 120-second worker-teardown leaks observed after failed paired journeys were diagnostic fallout and are not added to the original 14-test inventory.
