Fix False Markdown Rich-Mode Lockout on Prose Placeholders & Large Files

Users opening READMEs or docs containing CLI placeholders like <id> or <path> were falsely locked out of visual Rich Text editing with an un-dismissible warning banner claiming the file contains HTML/JSX. This PR distinguishes real HTML/JSX from plain prose placeholders and properly defers syntax checks behind size limits.

One-Line Problem
False "HTML Detected" Lockout
Markdown prose placeholders like <id> and <path> triggered aggressive HTML regex matches in documents >50KB, permanently disabling visual Rich Mode without an override option.
One-Line Fix
Schema-Aware Tag Validation & Deferred Parsing
Validates tag candidates against standard HTML tag lists and JSX patterns while deferring syntax blocking behind size limit warnings so users can cleanly use Rich Mode or click "Open anyway".
Scope Boundaries (What This PR Does vs. Does NOT Touch)
What This Change DOES (User Protections) What This Change Deliberately Does NOT Touch
PROSE PROTECTION

Allows common CLI placeholders in documentation (e.g., <id>, <path>, <username>) to render in visual Rich Mode without false-alarm lockouts.

 REAL HTML / JSX SAFETY

RECOVERABLE SIZE FALLBACK

 SIZE LIMIT PRESERVATION

UNIFIED ELIGIBILITY PIPELINE

Consolidates size and syntax checks into a single clean helper (getMarkdownRichModeEligibility) shared across the editor surface and panel render models.

 UNSUPPORTED SYNTAX RULES

Does NOT modify the strict fallback rules for footnotes ([^1]) or reference links ([label]: url), which remain exclusively in Code view.

Decision Traps: Myth vs. Reality
1. Severity Trap
Myth
"It's just a cosmetic fallback to Code mode; users can still read and edit the text."
Reality
It's a persistent usability blocker for non-technical users and doc writers. Files with simple CLI docs permanently lose rich visual editing, table editing, and checklist formatting.
2. Blast Radius Trap
Myth
"Allowing more tags might accidentally allow malformed HTML that corrupts documents during save."
Reality
Blast radius is strictly contained: standard HTML elements, custom JSX tags, closing tags, comments, and tags with attributes are still rejected. Only bare prose placeholders pass through.
3. Hold Risk Trap
Myth
"Holding this change until a full Markdown parser rewrite is safer."
Reality
Holding leaves hundreds of everyday technical READMEs, runbooks, and CLI guides broken in Rich Mode today. This 93-LOC surgical patch resolves the issue without architectural risk.
Risk Analysis & Final Recommendation
Who Benefits (Upside)
  • Document Authors & Engineers: Read and edit command guides, CLI references, and runbooks in Rich Mode without sudden lockouts.
  • Large File Editors: Can override file size limits via "Open anyway" without being blocked by false syntax flags.
  • Zero Performance Overhead: Tag check uses fast O(1) Set lookups with zero main-thread UI jank.
Who Pays / Potential Downside
  • Extremely Rare Custom HTML Tag: If a user uses an uncommon custom single-word tag without attributes or closing tags (e.g., <customtag>) that isn't standard HTML, it won't trigger the HTML blocker.
  • Mitigation: If such a tag fails the round-trip check on save, Rich Text error boundaries protect document integrity.
SHIP (Recommended)

WRONG TOOL
